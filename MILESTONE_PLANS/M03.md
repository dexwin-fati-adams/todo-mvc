Objective
What will this milestone achieve?
Define the todo data model, initial migration, database boundary, and migration proof.

Included
•   Created the Todo table with Drizzle, defined its fields and what each field should contain.
•   Set up Drizzle Kit and the first migration.
•   Added Docker Compose.
•   Connected the app to PostgreSQL using DATABASE_URL.
•   Added the Todo types and Zod validation.
•   Added the database schema and migrations.
•   Tested that everything installs, builds, and runs correctly.
•   Committed and pushed the changes.
Not included
•   Todo CRUD business logic or service layer.
•   API routes or HTTP handlers.
•   Authentication.
•   Frontend integration or UI.
Current repository evidence
What files, commands, or existing patterns did you inspect before making this plan?
•   M01 (branch chore/m02-repository-setup) established the pnpm workspace: apps/api, apps/web, packages/contracts, root tsconfig, eslint, and prettier.
•   apps/api and packages/contracts currently have no src/ directory and no database code.
•   packages/contracts has no shared schemas yet — this milestone adds the first one (Todo).
•   No Docker configuration exists yet in the repository.
Acceptance criteria
The Drizzle schema matches the approved todo model.
The real migration is generated from the schema source.
Generated migration files are not hand-edited.
The database connection is injected.
Persisted rows are validated at the repository boundary.
The migration proof uses an isolated disposable PostgreSQL database.
The proof covers an empty database, schema objects, constraints, a write, and a read.
API and PostgreSQL can be started locally with the documented Docker command.

Contracts
Input
Drizzle tells us what the Todo table should look like, DATABASE_URL tells us where the database is, and Zod makes sure the Todo data has the correct format.
Success
What exact value or visible result means success?
The database is created correctly, the migration works, the Todo table is correct, saving/finding/updating Todos works properly.


Expected failures
Before any implementation exists, these tests fail because the code they depend on doesn't exist yet: module-not-found errors for apps/api/src/db/schema.ts and apps/api/src/db/todos-repository.ts, and there is no todos table for the migration test to check.


Unexpected failures
Unexpected problems can come from Docker, the computer, the internet connection, or PostgreSQL/Drizzle. If something goes wrong, I will check the error, find the cause, fix it, and run the checks again before continuing.

Certainty Checks
1. What comes into the system?
The Todo table rules, the database address (DATABASE_URL), and Todo data.
2. How will you check it?
Create the migration, run it on PostgreSQL, and run the tests.
3. What should happen if everything works?
The migration is created, the database has the correct Todo table, and we can add and get a Todo.
4. What problems can happen?
Wrong schema, migration problems, database connection problems, missing DATABASE_URL, Docker not running, or wrong Todo data.
5. How will the problems be shown?
Drizzle or PostgreSQL will show an error, and the repository will show a Todo error.
6. Where will the routes, business rules, and UI be?
Not applicable
7. What will you test?
Check that the schema works, the migration works, and valid and invalid Todo data are handled correctly.
8. How will you test everything together?
Start PostgreSQL, run the migration, and run the repository tests.
9. Are we changing many records or using another system?
No. We are only testing adding and getting one Todo.

Implementation steps
•   Create the branch — Create a new Git branch for this work.
•   Check the branch — Make sure you are on the correct branch.
•   Create the Todo data schema — Add the Todo data type and Zod schema.
•   Create the database schema — Define how the Todo will be stored in the database.
•   Configure Drizzle — Tell Drizzle where the database schema and DATABASE_URL are.
•   Set up Docker Compose — Create a file that tells Docker how to start a PostgreSQL database for local development and testing.
•   Create .env.example — Show which database variable the app needs.
•   Start the database — Start the PostgreSQL database with Docker.
•   Create the migration — Use Drizzle to create the migration file.
•   Run the migration — Use the migration file to create the Todo table in the database.
•   Create the database client — Create the code that lets the app connect to PostgreSQL.
•   Create error types — Define the different errors the Todo system can return.
•   Create the Todo repository — Create the code that saves and gets Todo data without throwing errors.
•   Test the migration — Make sure the migration works and we can save and read a Todo.
•   Test invalid Todo data — Make sure invalid Todo data is rejected with the correct error.
•   Test missing database settings — Make sure the app gives an error when DATABASE_URL is missing.
•   Run all tests — Run everything to make sure the whole setup works.
•   Check Git status — See which files were created or changed.
•   Commit the changes — Save the changes in Git.
•   Push the branch — Send the branch to the Dexwin GitHub repository.
•   Create the Pull Request — Create a PR for M03 / feat/m04-todo-database-foundation.
