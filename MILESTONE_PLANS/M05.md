Contracts
Input
POST /todos
Content-Type: application/json

{
"title": "string"
}
Only title is read from the request. Any other field is ignored.
Success
201 Created
{
"id": "uuid",
"title": "string",
"completed": false,
"createdAt": "ISO-8601 timestamp",
"updatedAt": "ISO-8601 timestamp"
}
Success means one new row is saved, and the response shows that row.
Expected Failures
Failure
When it happens
How it is shown
MissingTitle
The title field is missing.
Result.err({ type: "MissingTitle" }). Returns 400.
EmptyTitle
The title is empty after trimming.
Result.err({ type: "EmptyTitle" }). Returns 400.
TitleTooLong
The title is longer than the max length
Result.err({ type: "TitleTooLong", max: 200 }). Returns 400.
InvalidTitleType
The title is not text, for example a number.
Result.err({ type: "InvalidTitleType" }). Returns 400.

Unexpected Failures
● Example: the database is down, or a query fails for a reason not listed above.
● These are caught at the repository. They become Result.err({ type: "UnexpectedError", cause }). The error is logged. The client only sees a plain 500 message, with no internal details.
● No error should ever escape without being caught. The route uses ts-pattern to handle every possible Result.
Responsibilities
Layer
What it does
Route
Reads the request. Checks it with Zod. Calls the service. Turns the Result into an HTTP response. Has no business rules.
Service
Takes the checked title. Decides what a new todo looks like (completed is false, plus id and timestamps if not left to the database). Calls the repository.
Repository
Runs the one INSERT into the todos table, using db.ts. Catches any database error and turns it into UnexpectedError. Returns the saved row.
Hook
Not applicable. This milestone has no frontend.
View
Not used. This milestone has no frontend.

Certainty Checks
What comes into the system?
A JSON body with one field: title.
How will it be checked?
A Zod schema checks that title is text, is trimmed, is not empty, and is not too long.
What does success return?
201, with id, title, completed, createdAt, and updatedAt.
What failures can happen?
MissingTitle, EmptyTitle, TitleTooLong, InvalidTitleType. All return 400.
How is each failure shown?
As a Result.err with a type field. The route matches every type with ts-pattern and turns it into a response.
Where does each part live?
Route: reads and checks the request. Service: decides what a new todo is. Repository: saves it to the database.
What tests come first?
Listed below. They cover the route, the service, the repository, and one real end-to-end test.
How will the whole flow be proven?
One test will call the real route with a real test database, and check the real row that gets saved.
