Requirements

Objective
Add only the All, Active, and Completed list filters.
Included
● The default behaviour when no status is given.
● The exact values that are accepted.
● The values that are rejected, and why.
● What happens if status is sent more than once.
● What happens if an unknown query field is sent.
● How the database query changes to support this.

Not Included
● Searching todos by text.
● Paging,
● Any new fields on the todo itself.
● Any frontend or UI work. This plan is for the backend only.
Current Repository Evidence
● The GET /todos route from M08. It reads all todos and returns them in one fixed order, oldest first.
● The todos table. It has a completed field, true or false. This is what the filter will use.
● db.ts. This file connects to the database. It was built in M04. This milestone will not change it.
● The style used so far: route, service, repository, with Zod for checks and Result types for errors. M10 will use the same style.

Acceptance Criteria
status=all|active|completed works as specified.
Omitting status means all.
Invalid, duplicate, and unknown query parameters are rejected.
