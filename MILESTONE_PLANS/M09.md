Certainty Checks
What comes into the system? A status value from the query string: all, active, or completed. Defaults to all if omitted.
How will it be checked? StatusQuerySchema (Zod) checks status is one of the three values, appears at most once, and — via .strict() — that no unknown query fields are sent.
What will it return on success? 200, list of todos filtered by status, same shape as M08.
What expected failures can happen? Missing/invalid status, duplicate status, unknown query field — all rejected before business logic runs.
How is each failure represented? 400, { error: "VALIDATION_ERROR", message: "..." }, built from Zod issues.
Where do the rules live? Allowed values/validation in todo.contracts.ts; route in todo.routes.ts; business rules in todo.service.ts; DB work in todo.repository.ts.
Tests before implementation? A repository test for status=all|active|completed, run against the real test database.
How is the whole operation proven through real boundaries? Repository test runs against the real test database, exercising actual SQL.
Multiple records or another system? No.
Frontend states? Not applicable — backend only.
