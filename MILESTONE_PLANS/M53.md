## Included

- **Clean start.** Clone the repository into a new folder, install dependencies with the lockfile, and start with an empty database volume.
- **One Docker Compose command** that builds and starts web, API and PostgreSQL. `<<CHECK: exact command and service names from docker-compose.yml>>`

## Contracts

### Input

- A clean clone of the repository at the final commit.
- An empty PostgreSQL volume.
- No existing `node_modules`, build output or test data.

### Success

- One documented command builds and starts web, API and PostgreSQL, and the application opens in the browser with an empty list.
- The migration runs for real and `\dt` shows the `todos` table.
- Every check command exits 0. Results are recorded with the exact command, date and commit SHA.
- Playwright passes all tests, including the recovery paths.
- The keyboard smoke test and the architecture explanation are completed by Fatimah.
- The final pull request has no unresolved critical finding.

### Keyboard smoke test (bounded)

Only Tab, Shift+Tab, Enter and Space. Time limit: `<<FILL: e.g. 10 minutes>>`. Journey: reach the create field, add a todo, toggle it, enter selection mode, select two, mark them complete, select one, delete it with the confirmation, and exit selection mode. Pass means every step works with no mouse, focus is always visible, and focus never lands somewhere unexpected. Record any failure with the step number.

### Architecture explanation

Fatimah explains, without notes: the layers (contracts, route, service, repository, adapter, hook, reducer and labels, flow, view); where rules live; the main contracts (`PATCH /todos/batch`, `POST /todos/batch-delete`, the conflict body); the failure paths (validation 400, conflict 409, network and 5xx, parse errors) and how each is represented as a value; and why batch operations are atomic.

### Expected failures during verification

| Failure                                 | Handling                                                               |
| --------------------------------------- | ---------------------------------------------------------------------- |
| A check fails on a clean clone          | Record it as a finding. Fix only if approved. Re-run the whole packet. |
| Compose fails to build or start         | Record the error and the service. Fix as an approved correction.       |
| Migration fails or the table is missing | Record. Do not apply it by hand to hide the problem.                   |
| A Playwright test is flaky              | Run it three times. Record the result. Do not skip or delete it.       |
| A critical finding is found             | Stop and tell the manager. Do not mark the milestone complete.         |

### Final evidence packet

A single document or PR section with: commit SHA; clean-clone steps with the date; the Compose command and its output; the migration output and `\dt`; each check command with its result; the Playwright summary and report; the CI run link; the journey-to-test map; the keyboard smoke test record; the architecture session record; the manager-selected change record; open findings (none critical).

## Risks and assumptions

- **M52 must be merged first.** If it is not, the clean clone will not contain the delete feature.

- **CI does not type-check `apps/web`.** I run `tsc --noEmit` there myself.
- **Playwright ports** are 4000 and 4001. Both must be free.
- **Docker must be running** before the clean start.
- **Flaky tests** are re-run three times and reported, never skipped.
- **Time:** remaining Week 16 time is used only for verification, approved corrections and existing contingency.
